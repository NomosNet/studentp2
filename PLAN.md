## Этап 1. Соглашения и cookies на сайте

Сейчас в футере нет юрссылок, баннера нет, в регистрации нет галочки согласия.

### 1.1. Страницы документов

- [ ] `/privacy` — политика обработки персональных данных
- [ ] `/cookies` — политика cookies
- [ ] `/terms` — пользовательское соглашение

В каждом тексте указать: **StudentPass**, email команды, дату. Данные, которые реально собираем: имя, email, вуз, пароль (хеш), cookie `access_token`.

### 1.2. Показать документы на сайте

- [ ] Ссылки в `SiteFooter.vue`
- [ ] Баннер cookies: «Принять» / «Только необходимые», решение в `localStorage`
- [ ] В форме регистрации обязательный чекбокс: согласие на обработку ПДн (без галочки регистрация не отправляется)

### 1.3. Проверка

- [ ] Баннер появляется у нового пользователя и не всплывает после выбора
- [ ] Ссылки из футера открывают страницы
- [ ] Регистрация без галочки не проходит

## Этап 2. SMTP для регистрации

Без SMTP код регистрации **не приходит на почту** — только в лог `studentpass-notify`. Вход в готовый аккаунт SMTP не требует.

### 2.1. Почта

- [ ] Завести почту для писем (Яндекс / Mail.ru / Gmail)
- [ ] Включить SMTP и получить пароль приложения (не обычный пароль от ящика)

### 2.2. Переменные

Файл `backend/.env` (из `.env.example`):

```env
SMTP_SERVER=smtp.yandex.ru
SMTP_PORT=587
SMTP_LOGIN=your-login@yandex.ru
SMTP_PASSWORD=your-app-password
```

- [ ] Заполнить все четыре переменные
- [ ] Перезапустить: `cd backend && docker compose up -d`

### 2.3. Проверка

- [ ] На сайте: Регистрация → «Получить код на почту» → письмо пришло
- [ ] Если нет письма: `docker logs studentpass-notify`

Демо без почты (только для проверки кабинетов): `admin` / `admin`, `manager` / `manager`.

## Этап 3. Подготовка к продакшену (нужно до залива на VPS)

Иначе сайт на домене откроется, а логин/регистрация сломаются.

- [ ] CORS: в `ApiGateway` и `ServiceUsers` сейчас только `http://localhost:5173`. Добавить `https://ваш-домен`
- [ ] Cookie `access_token`: на HTTPS поставить `Secure = true` (сейчас `false`)
- [ ] Сменить `JWT_SECRET_KEY` в `.env` (не оставлять dev-секрет)
- [ ] Сменить `POSTGRES_PASSWORD`
- [ ] На VPS **не открывать наружу** порты 5432, 6379, 5672, 15672, 8001
- [ ] Gateway не вешать на публичный `:80` — его займёт Nginx. Внутри: `127.0.0.1:8080:8000`
- [ ] Фронт собирать с `VITE_API_BASE_URL` на свой домен (или пусто, если Nginx отдаёт API с того же хоста)

## Этап 4. VPS

Минимум: 1 vCPU, 2 GB RAM, Ubuntu 22.04/24.04, Docker.

### 4.1. Сервер

- [ ] Арендовать VPS, сохранить IP
- [ ] SSH: `ssh root@IP`
- [ ] Обновить систему, поставить Docker и Docker Compose
- [ ] Создать пользователя не-root (по возможности) и ключ SSH
- [ ] Firewall: открыть только `22`, `80`, `443`

### 4.2. Код на сервере

```bash
git clone https://github.com/NomosNet/studentp2.git
cd studentp2
```

- [ ] Клонировать репозиторий
- [ ] На сервере создать `backend/.env` (SMTP, JWT, пароль БД) — **не коммитить**
- [ ] Собрать фронт: `cd frontend && npm ci && npm run build`
- [ ] Поднять бэкенд: `cd backend && docker compose up --build -d`

### 4.3. Nginx: сайт + API на одном домене

Схема:

```
браузер → https://домен
          ├── /        → фронт (frontend/dist)
          └── /api     → ApiGateway (127.0.0.1:8080)
```

- [ ] Установить Nginx
- [ ] Конфиг сайта: статика из `frontend/dist`, прокси `/api` на gateway
- [ ] `try_files` для Vue Router (`createWebHistory`), чтобы `/catalog` и `/privacy` не давали 404

## Этап 5. Домен и HTTPS

### 5.1. DNS

- [ ] Купить / взять домен
- [ ] A-запись `@` → IP VPS
- [ ] A-запись `www` → IP VPS (если нужен www)
- [ ] Подождать обновление DNS (`ping ваш-домен`)

### 5.2. Сертификат

- [ ] Certbot: `sudo certbot --nginx -d ваш-домен -d www.ваш-домен`
- [ ] Проверить автопродление: `sudo certbot renew --dry-run`
- [ ] Сайт открывается по `https://`, HTTP редиректит на HTTPS

### 5.3. Проверка после домена

- [ ] Главная, каталог, политики открываются
- [ ] Регистрация: код приходит на почту
- [ ] Вход работает, cookie ставится
- [ ] Админка / кабинет менеджера открываются
